# PlayBuilder UX Manifesto
Version: 1.0

Status: Living Document

Maintainer: Wine Country Flix

---

# Purpose

PlayBuilder exists to help collectors build the game library they actually want—not overwhelm them with ROM management.

The user should spend their time thinking about games.

Atlas should spend its time thinking about ROMs.

Whenever possible, Atlas should make intelligent decisions automatically and explain them in plain language.

---

# Mission Statement

PlayBuilder should be the easiest game collection manager to begin using while becoming the most powerful one available as the user grows.

Simple enough for someone's very first ROM collection.

Powerful enough for a museum archive.

---

# Principle 1 — Five Minute Success

A first-time user should be able to:

• Scan games

• Select systems

• Choose a collection

• Review the results

• Build a playable library

...within approximately five minutes.

Documentation should never be required for the common workflow.

---

# Principle 2 — Progressive Disclosure

Never show advanced controls until they are needed.

Common workflows should remain simple.

Advanced workflows should remain powerful.

Example:

1G1R

✓ Collection Type

✓ Preferred Style

✓ Systems

✓ Games

✓ Review Build

Custom

✓ Language Ranking

✓ Region Ranking

✓ Revision Rules

✓ Translation Rules

✓ Atlas Configuration

---

# Principle 3 — Don't Make Me Learn Atlas

Atlas is an engine.

PlayBuilder is the interface.

Users should never need to understand Atlas terminology to use PlayBuilder successfully.

Instead of:

Eligibility

Revision Rule

Candidate Evaluation

Show:

Why this version?

Newest release

English preferred

Better than Japanese version

---

# Principle 4 — Speak Human

Use words collectors naturally understand.

Good:

English First

USA First

Excluded Games

Missing Artwork

Duplicate Games

Avoid exposing internal implementation terminology unless the user explicitly enters Advanced mode.

---

# Principle 5 — One Screen. One Job.

Each page should answer exactly one question.

Home

Where am I?

Scan

Where are my games?

Library

What games do I own?

Collections

Which games do I want?

Build Preview

What will happen if I click Build?

Settings

How should PlayBuilder behave?

If a page answers multiple unrelated questions, split it.

---

# Principle 6 — Smart Defaults

The first recommendation should almost always be correct.

A user should rarely need to modify Atlas decisions.

---

# Principle 7 — Explain Decisions

Every automatic decision should answer:

Why?

Never expose internal engine reasoning.

Instead explain the result in plain English.

---

# Principle 8 — Respect the Collector

Never delete automatically.

Always quarantine.

Always allow review.

Always allow recovery.

Collectors trust software that protects their collection.

---

# Principle 9 — Power Without Fear

Advanced users should never lose functionality.

Beginners should never be overwhelmed.

Hide complexity.

Do not remove it.

---

# Principle 10 — Make It Feel Alive

Celebrate progress.

Example:

✓ 34,220 games selected automatically

Only 12 games need your attention.

instead of

Scan Complete

---

# Principle 11 — Let the User Build Their Way

PlayBuilder should never assume one collection is correct.

Support:

USA

Europe

Japan

English

Favorites

Complete Sets

Custom

All should be first-class workflows.

---

# Principle 12 — Software Should Stay Out of the Way

The user came to build a game collection.

Not configure software.

If they spend more time learning PlayBuilder than building collections...

PlayBuilder has failed.

---

# Principle 13 — Preserve Trust

Every action should be:

Predictable

Explainable

Reversible

The Build button should never feel risky.

---

# Principle 14 — Every Click Should Feel Worthwhile

Buttons should always produce visible results.

No dead clicks.

No silent failures.

No confusing UI.

Every interaction should provide immediate feedback.

---

# Final Promise

PlayBuilder should never be the smartest application in the room.

It should simply make the user feel like they are.
